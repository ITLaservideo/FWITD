# utils

JS utilities and core framework modules. Loaded on demand — auto-detected by scanning each app's JS source for the enum member names (`JS.utils`, `JS.frameworks`).

## Subfolders

### `frameworks/`

Core runtime modules loaded unconditionally into every page:

| File | Enum | Description |
|---|---|---|
| `FrameworkGC.js` | `JS.frameworks.FrameworkGC` | Base class / garbage-collected component lifecycle. Contains the `{{@owner_id}}` placeholder replaced with the WebView ID. |
| `AppStatus.js` | `JS.frameworks.AppStatus` | App-level state manager. `{{@AppSettings.key}}` placeholders are replaced with values from `AppSettings` at load time. |
| `google3.woff2` | — | Material Symbols icon font, embedded as Base64 into `styles.css` via `@BASE64FrameworkIcons`. |

### `external_libs/`

Vendored third-party libraries, shipped as `Name.js` / `Name.min.js`. The `.min.js` files are regenerated by `MinifyClientApp` like every other ClientApp file, so each `Name.js` opens with a `/*keep @license ... */` block that collects the library's license notice plus those of everything it bundles: `MinifyClientApp` only preserves `keep` comments, and the inline notices further down the file are stripped. Keep that block at the very top of the file (above any IIFE wrapper), and extend it whenever a library is updated or a new one is added. `JSProvider.JS.getJSExternalLibs` scans each app's fully assembled script (the page/injectable plus every component bundled into it) for the globals a library exposes, and prepends each library that's found exactly once, in `JS.external_libs` declaration order. That holds even when several components use the same library, e.g. `ExportDataButton` and `DataCruncher` both use `XLSX`.

| File | Enum | Triggered by | Also loads |
|---|---|---|---|
| `XLSX.js` | `XLSX` | `XLSX` | |
| `html2canvas.js` | `html2canvas` | `html2canvas` | |
| `jsPDF.js` | `jsPDF` | `jsPDF`, `jspdf` | |
| `pdf-lib.js` | `pdf_lib` | `exportsPDFLIB`, `PDFLib` | |
| `pdf.js` | `pdf` | `pdfjsLib` | `pdf.worker.js` inlined into it |

`pdf.worker.js` is not a library of its own: `JSProvider` (`external_libs_inlined`) escapes its source into the `${injector_pdf_worker}` template-literal placeholder at the end of `pdf.js`, which starts it as a real Web Worker from a Blob URL (or, if that fails, evaluates it on the main thread for pdf.js's "fake worker"). Its wasm image codecs live in `pdfjs_wasm/` (embedded, served by `App/GetPdfJsWasm`), see that folder's readme.

Using a library's global in code is enough. A `//keep XLSX` comment works too: a leading `//keep` line survives minification. To add a library, drop both files here, then add an enum member and an `external_libs_info` entry (file name, trigger globals, required libs) in `JSProvider.cs`. Pick triggers specific enough that they don't appear in unrelated code, or every page ends up bundling the library. These files are excluded from every `jsconfig.json` to stay under the JS/TS language-service size limit.

### `translations/`

i18n data files consumed by the `Locale` utility:

| File | Language |
|---|---|
| `it.js` / `it.min.js` | Italian (default — `default_language = "it"`) |
| `en.js` / `en.min.js` | English |
| `de.js` / `de.min.js` | German |

Each file exports `const data = { ... }`. The C# loader strips the `const data =` declaration and splices the JSON literal directly into `Locale.js` at the `"{{@jsonTranslations}}"` placeholder.

## Utility modules

Each file ships as `Name.js` (debug) and `Name.min.js` (release):

| File | Enum | Description |
|---|---|---|
| `AppRouter.js` | `JS.utils.AppRouter` | Client-side route management |
| `Icons.js` | `JS.utils.Icons` | Named icon lookup and SVG injection |
| `Lobby.js` | `JS.utils.Lobby` | WebView↔native message bridge. Replaces `{{@HttpImagesAddress}}` with the image server address. The platform-specific `FWBridge` shim is injected by `JSProvider` at bundle assembly time. |
| `Locale.js` | `JS.utils.Locale` | i18n — receives the translation JSON at assembly time |
| `Logger.js` | `JS.utils.Logger` | Structured console logger |
| `MovableUtil.js` | `JS.utils.MovableUtil` | Drag-to-reposition helper for floating elements |
| `SpaHistory.js` | `JS.utils.SpaHistory` | In-page navigation history stack |
| `UiBuilder.js` | `JS.utils.UiBuilder` | Declarative DOM construction helpers |

## Adding a utility

1. Create `MyUtil.js` and `MyUtil.min.js` in this folder.
2. Add `MyUtil` to the `JS.utils` enum in `JSProvider.cs`.
3. Any app that references `MyUtil` by name in its JS will have it included automatically.
